# 공시 질의응답 (QA)

사용자 질문을 받아 DB에 저장된 공시를 검색하고, 검색한 공시 원문만 근거로 답변을 만드는 기능을 설명한다.
코드는 `backend/src/qa/`에 있고, API는 `POST /qa/ask`이다.

이 문서는 두 부분으로 나뉜다.

- **1~6장 (발표용):** 무엇을 어떻게 했고 왜 그렇게 했는지. 예시는 모두 실제로 실행한 결과다.
- **7~11장 (개발 참고용):** 파일 구성, API, 검색 SQL, 프롬프트 규칙.

공시를 수집해 DB에 넣는 과정(파싱·청킹·임베딩·적재)은 [ingest.md](ingest.md)를 참고한다.

---

## 1. 한 줄 요약

**질문을 받으면 LLM이 공시 검색이 필요한지 판단하고, 필요하면 회사와 기간을 확인해 공시를 검색한 뒤, 검색한 원문만 근거로 출처 번호를 붙여 답한다.**

- 공시에 없는 내용은 지어내지 않고 "확인되지 않습니다"라고 답한다.
- 답변의 모든 근거에 공시명, 공시일, 접수번호, 원문 위치(목차 경로), DART 원문 링크를 붙인다.
- 원문에서 확인한 사실과 LLM의 해석을 구분해 쓴다 (`해석:` 단락).

현재 DB에 있는 공시 (테스트 기준)

| 기업       | 공시                 | 공시일     |
| ---------- | -------------------- | ---------- |
| 삼성전자   | 사업보고서 (2023.12) | 2024.03.12 |
| 삼성전자   | 분기보고서 (2026.09) | 2026.11.16 |
| SK하이닉스 | 반기보고서 (2026.06) | 2026.08.14 |
| SK하이닉스 | 분기보고서 (2026.09) | 2026.11.16 |

## 2. 전체 흐름

```
사용자 질문
   │
   ▼
① 1차 LLM: 질문 판단 ─────────────── 공시를 찾을 필요 없음 (인사, 사용법, 투자 추천 요청)
   │  공시 검색이 필요하면                  └→ LLM이 바로 답변 (근거 없음)
   │  검색 조건을 채워서 요청
   │  (찾을 내용, 회사, 공시 종류, 기간, "최근" 여부)
   ▼
② 회사 확인 ───────────────────────── DB에 없는 회사
   │                                     └→ "○○의 공시가 없습니다. 조회할 수 있는 기업: …"
   ▼
③ 기간 확인 ───────────────────────── 그 기간 공시가 DB에 없음
   │  "최근"이면 DB에서 가장 최근 공시를 고름   └→ "○○ 공시가 없습니다. 조회할 수 있는 공시: …"
   ▼
④ 검색: 질문과 의미가 가까운 공시 조각 5개 (회사·기간 조건 안에서)
   │
   ▼
⑤ 2차 LLM: 검색된 원문만 보고 답변 작성, 문장마다 근거 번호 [1] [2] …
   │
   ▼
답변 + 근거 목록 (공시명 · 공시일 · 접수번호 · 원문 위치 · 발췌 · DART 링크)
```

**용어**

| 용어         | 뜻                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------- |
| 청크 (chunk) | 공시를 검색하기 좋은 크기로 나눈 조각. 본문 문단 묶음이나 표 일부. 공시 1건에 1,600~3,200개 |
| 임베딩       | 글의 의미를 숫자 1,536개(벡터)로 바꾼 것. 의미가 비슷한 글은 벡터도 가깝다                  |
| 벡터 검색    | 질문도 벡터로 바꿔서, 벡터가 가장 가까운 청크를 찾는 검색                                   |
| tool 호출    | LLM이 "이 함수를 이 인자로 불러 달라"고 요청하는 기능. 여기서는 공시 검색 함수              |

## 3. 질문 유형별 동작 (실제 예시)

응답 시간은 로컬 개발 환경에서 잰 값이다.

### 3.1 일반 대화 → 검색 없이 바로 답변

> **Q.** 안녕! 이 서비스는 뭘 할 수 있어?
>
> **A.** 안녕하세요! 국내 상장기업의 DART 사업보고서·반기보고서·분기보고서를 바탕으로 재무 수치, 사업 내용, 위험 요인, 배당, 임원 정보 등을 찾아드릴 수 있어요. 궁금한 회사와 내용을 말씀해 주세요.

LLM을 한 번만 부른다 (3.1초).

### 3.2 투자 추천 요청 → 거절하고 대안 안내

> **Q.** 삼성전자 주식 지금 사도 돼?
>
> **A.** 매수 여부나 투자 판단은 제공할 수 없습니다. 원하시면 삼성전자의 최근 실적이나 공시된 위험 요인을 찾아드릴 수 있습니다.

### 3.3 회사 + 기간을 말한 질문 → 그 공시 안에서만 검색

> **Q.** 삼성전자 2026년 3분기 매출 알려줘
>
> **A.** 삼성전자의 2026년 3분기(제58기 3분기, 3개월) **연결 매출액은 195,253,209백만원**(약 195조 2,532억 900만원)입니다.[1]
>
> [1] 삼성전자 분기보고서 (2026.09) · III. 재무에 관한 사항 > 2. 연결재무제표 · 접수번호 20261116001482

- LLM이 채운 검색 조건: 회사 `삼성전자`, 종류 `분기보고서`, 기간 `2026.09`
- 원문 수치를 그대로 옮기고 단위, 기간(제58기 3분기), 연결/별도 구분을 함께 적는다.

> **Q.** 하이닉스 2026년 상반기 위험 요인 알려줘
>
> **A.** SK하이닉스 **2026년 6월 반기보고서 기준** 주요 위험 요인은 환위험과 이자율위험입니다. …
>
> | 통화 |           연결 |           별도 |
> | ---- | -------------: | -------------: |
> | USD  | 4,751,654 증가 | 4,368,354 증가 |
> | JPY  | (118,394) 감소 | (108,174) 감소 |
> | …    |                |                |
>
> 이자율이 100bp 상승하면 … 법인세비용차감전순이익이 **연결 기준 19,855백만원**, **별도 기준 20,893백만원 감소**하는 것으로 공시됐습니다. [2][4]
>
> _해석:_ 공시된 민감도 기준으로는 환율 변동에 따른 손익 영향이 통화별로 다르며, …
>
> 근거 5건 모두 SK하이닉스 반기보고서 (2026.06)

- "하이닉스"라는 줄임말을 DB의 기업명 `SK하이닉스`로 연결했다.
- "2026년 상반기"를 `반기보고서 / 2026.06`으로 바꿨다.
- 사실(수치)과 `해석:`을 나눠 썼다.

### 3.4 "최근" 질문 → 시스템이 가장 최근 공시를 고름

> **Q.** 삼성전자 최근 공시 내용 알려줘
>
> **A.** 삼성전자 **2026년 9월 분기보고서**에서 확인되는 주요 내용은 다음과 같습니다.
>
> - **주요 계약:** Netlist와 2026년 8월 4일 상호 특허 사용 계약을 체결했으며, … [2][3]
> - **주요 주주 변동:** … [4]
> - **임원 주식보상:** … [5]

- LLM은 "최근"이라는 표시(`latest`)만 하고, **실제 가장 최근 공시(분기보고서 2026.09)는 코드가 DB에서 골랐다.**

### 3.5 DB에 없는 기간 → 검색하지 않고 있는 공시를 안내

> **Q.** 하이닉스 2025년 사업보고서 위험 요인 알려줘
>
> **A.** SK하이닉스 사업보고서 2025.12 공시가 없습니다. 현재 조회할 수 있는 공시: 분기보고서 (2026.09), 반기보고서 (2026.06)

검색과 2차 LLM을 건너뛰어 빠르다 (2.3초).

### 3.6 DB에 없는 회사 → 검색하지 않고 있는 기업을 안내

> **Q.** LG전자 매출 알려줘
>
> **A.** LG전자의 공시가 없습니다. 현재 조회할 수 있는 기업: 삼성전자, SK하이닉스

다른 회사 공시로 엉뚱하게 답하지 않는다.

### 3.7 기간을 말하지 않은 질문 → 그 회사의 모든 공시에서 검색

> **Q.** SK하이닉스 HBM 사업 현황 알려줘
>
> **A.** SK하이닉스는 HBM이 AI·딥러닝 워크로드 증가에 따라 … AI 시대에 최적화된 메모리라고 설명합니다. [1] …
>
> 해석: … 다만 제공된 공시에서 HBM 매출액, 시장점유율, 생산량 및 구체적인 제품별 실적은 확인되지 않습니다.

- 근거에 없는 내용(매출액, 점유율)은 추측하지 않고 "확인되지 않습니다"라고 밝혔다.

### 3.8 이어지는 질문 → 이전 대화에서 회사·기간을 이어받음

> **Q1.** 하이닉스 2026년 상반기 매출 알려줘
>
> **A1.** SK하이닉스의 2026년 상반기(제79기 반기) 연결 기준 매출액은 **131,895,033백만원**입니다. [1][4]
>
> **Q2.** 그럼 영업이익은?
>
> **A2.** 연결 기준 영업이익은 **제79기 반기 누적 98,152,891백만원**이며, **3개월 기준 60,542,608백만원**입니다. [4]
>
> **Q3.** 삼성전자는?
>
> **A3.** 삼성전자 반기보고서 2026.06 공시가 없습니다. 현재 조회할 수 있는 공시: 분기보고서 (2026.09), 사업보고서 (2023.12)

- Q2: 회사·기간이 없지만 이전 대화에서 `SK하이닉스 / 반기보고서 / 2026.06`을 이어받고, 찾을 내용만 `영업이익`으로 바꿨다.
- Q3: 회사만 `삼성전자`로 바꾸고 기간(2026.06)과 찾을 내용(영업이익)은 이어받았다. 삼성전자는 그 기간 공시가 없어서 조회 가능한 공시를 안내했다.

> **Q1.** 하이닉스 HBM 사업 현황 알려줘 → SK하이닉스 공시로 답변
>
> **Q2.** LG전자는? → "LG전자의 공시가 없습니다. 현재 조회할 수 있는 기업: 삼성전자, SK하이닉스"

## 4. 설계 결정과 이유

### 4.1 LLM을 두 번 부른다 (판단 → 답변)

|         | 하는 일                                                    | 받는 것                 |
| ------- | ---------------------------------------------------------- | ----------------------- |
| 1차 LLM | 공시 검색이 필요한지 판단하고, 필요하면 검색 조건을 정한다 | 사용자 질문 + 이전 대화 |
| 2차 LLM | 검색된 원문만 보고 답한다                                  | 질문 + 검색된 청크 5개  |

**이유:** 질문을 그대로 검색하면 "안녕" 같은 인사에도 공시를 찾게 되고, 회사명이나 기간이 섞인 질문은 검색 정확도가 떨어진다. 1차 LLM이 질문을 **찾을 내용 / 회사 / 공시 종류 / 기간**으로 나눠 주므로, 회사와 기간은 정확한 조건(필터)으로 걸고 찾을 내용만 의미 검색에 쓴다.

예: "하이닉스 2026년 상반기 위험 요인 알려줘" → 찾을 내용 `위험 요인`, 회사 `SK하이닉스`, 종류 `반기보고서`, 기간 `2026.06`

### 4.2 회사는 DB에 있는 목록에서만 고르게 한다

LLM에게 회사명을 자유롭게 쓰게 하지 않고, **DB에 공시가 있는 기업 목록 중에서만** 고르게 한다. 질문에 나온 회사명(`하이닉스`)과 목록에서 고른 회사(`SK하이닉스`)를 따로 받는다.

| 질문에 나온 회사 | 목록에서 고른 회사 | 동작                                     |
| ---------------- | ------------------ | ---------------------------------------- |
| 하이닉스         | SK하이닉스         | SK하이닉스 공시 안에서만 검색            |
| LG전자           | 없음               | 검색하지 않고 "LG전자의 공시가 없습니다" |
| 없음             | 없음               | 전체 공시에서 검색                       |

**이유:** 회사 조건 없이 검색하면 "LG전자 매출"에 삼성전자 매출로 답하는 사고가 생긴다. 삼성전자와 SK하이닉스처럼 같은 반도체 업종이면 내용이 비슷해서 더 쉽게 섞인다. 목록에서만 고르게 하면 엉뚱한 회사로 답할 수 없다.

### 4.3 "최근"은 LLM이 아니라 코드가 정한다

LLM은 DB에 어떤 공시가 있는지 모른다. "최근"을 LLM에게 맡기면 오늘 날짜로 기간을 추측하는데, 그 기간 공시가 아직 없으면 공시가 있는데도 "없습니다"라고 답하게 된다. 그래서 LLM은 "최근 질문이다"라는 표시만 하고, **코드가 DB에서 그 회사의 실제 가장 최근 공시를 고른다.** "최신 반기보고서"처럼 종류를 말하면 그 종류 중 가장 최근 것을 고른다.

### 4.4 없는 회사·기간은 검색하지 않고 바로 안내한다

DB에 없는 회사나 기간을 물으면 검색해 보고 "근거를 찾지 못했습니다"로 끝내지 않고, 검색 전에 확인해서 **지금 조회할 수 있는 기업이나 공시 목록**을 알려 준다. 사용자가 무엇을 다시 물어야 할지 알 수 있다. 이 답변은 LLM을 부르지 않고 코드로 만들기 때문에 빠르고 비용이 없다.

### 4.5 답변은 검색된 원문만 근거로, 번호를 붙인다

2차 LLM에게 주는 규칙 (요약)

1. 근거에 있는 내용만 쓴다. 없으면 추측하지 않고 "제공된 공시에서 확인되지 않습니다"라고 쓴다.
2. 근거를 쓴 문장 끝에 `[1]`, `[2]` 번호를 붙인다. "확인되지 않습니다" 문장에는 붙이지 않는다.
3. 수치는 원문 그대로 옮기고 단위, 기간, 연결/별도를 함께 적는다.
4. 해석은 `해석:` 단락에 따로 쓴다.

**이유:** 공시 서비스는 정확성과 신뢰가 핵심이다. 사용자가 답변의 숫자를 DART 원문에서 바로 확인할 수 있어야 한다. 그래서 답변 아래 근거 목록에는 **답변에서 실제로 인용한 번호만** 넣고, 각 근거에 공시명·공시일·접수번호·원문 위치·발췌·DART 링크를 붙인다.

### 4.6 이전 대화는 1차 LLM에만 넘긴다

프론트가 질문할 때마다 지금까지의 대화(질문과 답변 본문)를 함께 보낸다. 서버는 대화를 저장하지 않는다.

|         | 이전 대화를 받나 | 이유                                                                                                                    |
| ------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 1차 LLM | 받는다           | "그럼 영업이익은?"의 회사·기간을 이전 대화에서 알아내야 한다                                                            |
| 2차 LLM | 받지 않는다      | 이전 답변을 보면, 이번 검색 근거에 없는 내용을 이전 답변에서 가져다 쓸 수 있다. 답변은 항상 이번 검색 근거만으로 만든다 |

| 확인 항목      | 질문 예                                               | 결과                                                     |
| -------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| 일반 대화 구분 | 안녕! 이 서비스는 뭘 할 수 있어?                      | ✅ 검색 없이 답변                                        |
| 투자 추천 거절 | 삼성전자 주식 지금 사도 돼?                           | ✅ 거절 후 공시 조회 안내                                |
| 회사 필터      | 삼성전자 반도체 위험 요인 / 하이닉스 위험 요인        | ✅ 해당 회사 공시만 근거 (비슷한 업종이어도 섞이지 않음) |
| 줄임말 회사명  | 하이닉스 …                                            | ✅ SK하이닉스로 연결                                     |
| 없는 회사      | LG전자 매출 알려줘                                    | ✅ "공시가 없습니다" + 조회 가능 기업                    |
| 기간 필터      | 하이닉스 2026년 상반기 / 삼성전자 2026년 3분기        | ✅ 해당 기간 공시만 근거                                 |
| 없는 기간      | 하이닉스 2025년 사업보고서                            | ✅ "공시가 없습니다" + 조회 가능 공시                    |
| "최근"         | 삼성전자 최근 공시 / 요즘 실적                        | ✅ 가장 최근 공시(2026.09) 선택                          |
| "최근" + 종류  | 하이닉스 최신 반기보고서                              | ✅ 반기보고서 2026.06 선택                               |
| 근거 없는 내용 | SK하이닉스 HBM 사업 현황 (근거에 HBM 매출액이 없음)   | ✅ 매출액은 추측하지 않고 "확인되지 않습니다"            |
| 이어지는 질문  | 하이닉스 상반기 매출 → 그럼 영업이익은? → 삼성전자는? | ✅ 회사·기간을 이어받고, 새로 말한 회사만 바꿈           |
| 입력 검증      | 빈 질문, top_k 범위 밖                                | ✅ 422 오류                                              |

응답 시간: 일반 대화·없는 회사/기간 2~4초, 공시 검색 답변 9~13초.

| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `pipeline.py`  | 전체 흐름. `ask(question, top_k, history)` → `AskResponse`. 1차 LLM 호출, 회사·기간 확인, 검색, 답변                |

| ---------- | --------------------------------------------------------------------------------------------------------------------------------- |

## 9. 1차 LLM: 판단과 검색 조건 (`tools.py`, `ROUTER_SYSTEM`)

1차 LLM에는 `search_disclosures` tool이 연결되어 있다. LLM은 tool 설명과 인자 설명을 읽고, 공시 질문이면 tool을 호출하면서 인자를 채운다.

| 인자                | 설명                                                      | 예                  |
| ------------------- | --------------------------------------------------------- | ------------------- |
| `query`             | 찾을 내용만. 회사명·기간은 빼고 쓴다                      | `위험 요인`, `매출` |
| `mentioned_company` | 질문에 나온 회사명 그대로                                 | `하이닉스`          |
| `corp_name`         | `CorpName` 목록 중 해당 회사. 없으면 비움                 | `SK하이닉스`        |
| `report_type`       | `사업보고서` \| `반기보고서` \| `분기보고서`              | `반기보고서`        |
| `period`            | `YYYY.MM`. 연도와 기간(연간·상반기·분기)이 함께 나올 때만 | `2026.06`           |
| `latest`            | 질문에 "최근", "최신", "요즘"이 있을 때만 true            | `true`              |

`ROUTER_SYSTEM` 규칙 (요약)

1. 기업·공시·재무·사업·위험·배당·임원 등 공시로 확인할 질문은 반드시 tool을 호출한다. 알고 있는 내용이어도 기억으로 답하지 않는다.
2. 인사, 서비스 소개, 사용 방법은 tool 없이 짧게 답한다.
3. 매수·매도, 투자 추천, 주가 예측은 tool 없이 거절하고 공시 조회를 안내한다.
4. "작년", "올해 상반기"는 오늘 날짜 기준으로 바꾼다. "최근", "최신"은 기간으로 바꾸지 않고 `latest`를 true로 한다.
5. 회사나 기간을 생략한 질문은 이전 대화에서 이어받는다. 새 회사·기간을 말하면 새 값을 쓴다. 이전 답변으로 답하지 않고 공시 질문이면 매번 검색한다.

1차 LLM에 넘기는 메시지 순서: `system(ROUTER_SYSTEM)` → 이전 대화(`user`/`assistant`) → 이번 질문(`user`).

LLM이 채운 인자는 `SearchDisclosuresArgs`(Pydantic)로 다시 검증한다. 검증에 실패하면 어느 인자가 틀렸는지에 따라 안내한다 (10.1의 2번). tool을 여러 번 호출해도 지금은 첫 번째만 쓴다.

## 10. 회사·기간 확인과 검색 (`pipeline.py`, `retriever.py`)

### 10.1 처리 순서

| 순서 | 조건                                       | 동작                                                                                                     |
| ---- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 1    | tool 호출 없음                             | 1차 LLM 응답을 그대로 반환 (`type: general`)                                                             |
| 2    | 인자 검증 실패                             | `corp_name`이 목록 밖: "○○의 공시가 없습니다" / `report_type`이 사업·반기·분기보고서가 아님(감사보고서 등): "○○ 공시는 조회할 수 없습니다. 조회할 수 있는 공시 종류: …" / 그 외: "질문을 이해하지 못했습니다…" |
| 3    | `mentioned_company` 있음, `corp_name` 없음 | "○○의 공시가 없습니다. 현재 조회할 수 있는 기업: …"                                                      |
| 4    | `latest` + 회사 있음                       | DB 공시 목록에서 그 회사의 가장 최근 공시(종류를 말했으면 그 종류 중)로 `report_type`, `period`를 정한다 |
| 5    | `report_type`이나 `period` 있음            | DB 공시 목록에 맞는 공시가 없으면 "○○ 공시가 없습니다. 현재 조회할 수 있는 공시: …"                      |
| 6    | 그 외                                      | 값이 있는 조건(회사, 종류, 기간)으로만 좁혀서 검색                                                       |
| 7    | 회사를 지정했는데 검색 결과 0개            | DB에 그 회사 공시가 없으면 "○○의 공시가 없습니다" (`CorpName`에는 있지만 아직 적재하지 않은 경우). 공시는 있으면 "질문과 관련된 공시 근거를 찾지 못했습니다" (11.2) |
| 8    | 검색 결과 있음                             | 2차 LLM으로 답변 (11장)                                                                                  |

- `latest`인데 회사가 없으면(예: "최근 반도체 업황") 기업마다 최근 공시가 달라 고를 수 없으므로 전체 기간에서 검색한다.
- 공시 목록(`list_filings`)은 `filing` 테이블에서 `is_latest = true`인 공시만, 기간이 최근인 순서로 가져온다. 정정 전 옛 공시는 빠진다.

### 10.2 검색 SQL

```sql
SELECT chunk_id, kind, section_path, raw, rcept_no,
       1 - (embedding <=> %(q)s) AS score,
       meta->>'corp_name' AS corp_name,
       meta->>'report_nm' AS report_nm,
       meta->>'rcept_dt'  AS rcept_dt
FROM chunk
WHERE embedding IS NOT NULL
  AND meta @> %(filter)s
ORDER BY embedding <=> %(q)s
LIMIT %(k)s
```

- **질문 임베딩:** 1차 LLM이 정리한 `query`(예: `위험 요인`)를 임베딩한다. 원래 질문이 아니다.
- **유사도:** `<=>`는 pgvector의 코사인 거리다. `score = 1 - 거리`이고 1에 가까울수록 비슷하다.
- **필터:** `meta @> {"corp_name": "SK하이닉스", "report_type": "반기보고서", "period": "2026.06"}`처럼 값이 있는 조건만 넣는다. 조건이 없으면 `{}`로 전체를 검색한다. `chunk.meta`의 GIN 인덱스를 쓴다.
- **검색 대상:** 임베딩이 있는 청크만 (`text`, `table_kv`, 일부 `table`). 섹션 전체(`section`) 청크는 임베딩이 없어 검색되지 않는다 ([ingest.md](ingest.md) 3.4).
- **근거 정보:** 기업명, 공시명, 공시일은 `chunk.meta`에서 읽는다. DART 링크는 접수번호로 만든다 (`https://dart.fss.or.kr/dsaf001/main.do?rcpNo=<접수번호>`).
- 키워드 검색과 리랭커(검색 결과 재정렬)는 없다 (6장).

## 11. 2차 LLM: 답변 생성 (`answerer.py`, `ANSWER_SYSTEM`)

### 11.1 LLM에게 주는 근거 형식

검색 결과마다 번호, 공시, 원문 위치를 붙인다.

```
[근거]
[1] 삼성전자 분기보고서 (2026.09) · III. 재무에 관한 사항 > 2. 연결재무제표
2-2. 연결 손익계산서 | 단위: 백만원 | 연결
매출액 (주27)(제 58 기 3분기 / 3개월)=195,253,209 백만원; …

[2] …

[질문]
삼성전자 2026년 3분기 매출 알려줘
```

- 근거 본문은 청크의 `raw`(원문)를 쓴다. 검색용 `text`가 아니다.
- 근거 1건은 최대 2,000자까지 넣고, 넘으면 `...(중략)`으로 자른다 (긴 표 대비).
- **질문은 1차 LLM이 정리한 `query`가 아니라 사용자의 원래 질문**을 넣는다. 답변은 사용자가 물은 그대로에 맞춰야 하기 때문이다.

### 11.2 근거 목록 만들기

- 답변 본문에서 `[n]`을 찾아, **실제로 인용한 번호만** `sources`에 넣는다. 검색됐지만 쓰이지 않은 청크는 빠진다.
- 범위 밖 번호(예: 근거가 5개인데 `[7]`)는 버린다.
- `quote`는 원문 앞 300자이고, 넘으면 `...`을 붙인다.
- 검색 결과가 0개면 2차 LLM을 부르지 않고 "질문과 관련된 공시 근거를 찾지 못했습니다"를 돌려준다.
